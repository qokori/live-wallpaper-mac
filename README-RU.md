# Live Wallpaper для macOS

Живые обои для Mac: видео или веб-страница (HTML/CSS/JS, WebGL-шейдеры) на рабочем столе под иконками.
Приложение живёт в строке меню, без иконки в Dock. AppKit + AVFoundation + WebKit, SwiftUI только для меню,
без сторонних зависимостей. Лицензия MIT.

**Статус:** видео-обои проверены вживую на MacBook (Apple M5, macOS 27.0.1); веб-обои собраны и покрыты тестами,
но вживую ещё не запускались — см. «Ручная проверка». Сцены Wallpaper Engine не поддерживаются.

## Сборка и запуск

Нужен Xcode с Swift 6 (проверено на Xcode 27.1, Swift 6.4), macOS 14 или новее.

```sh
git clone https://github.com/qokori/live-wallpaper-mac.git
cd live-wallpaper-mac
swift test                               # тесты логики (40 шт.)
./scripts/build-app.sh                   # build/LiveWallpaper.app + копия в ~/Applications
SKIP_INSTALL=1 ./scripts/build-app.sh    # только build/, ничего не устанавливает
open ~/Applications/LiveWallpaper.app
```

Сборка universal (arm64 + x86_64), подпись ad-hoc, без нотаризации. Если Gatekeeper блокирует первый запуск:
правый клик → **Открыть**, либо `xattr -dr com.apple.quarantine ~/Applications/LiveWallpaper.app`.

## Меню

| Пункт | Что делает |
| --- | --- |
| строка статуса | «Играет», «Пауза: обои закрыты окнами», «Играет на 1 из 2 экранов»… |
| Видео… | mp4 / mov / m4v (H.264, HEVC и всё, что играет AVFoundation) |
| Веб-страница: папка или файл… | папка с `index.html` или отдельный `.html` |
| Веб-страница по адресу… | `https://…` (адрес без схемы получает `https://`) |
| Своё на каждый экран | у каждого экрана подменю с теми же тремя пунктами и «Как общие»; экран без своих обоев берёт общие |
| Убрать обои | убирает обои и возвращает прежнюю картинку рабочего стола |
| Пауза | вручную (не запоминается между запусками) |
| Пауза от батареи | пауза, пока Мак работает от батареи (по умолчанию выкл.) |
| Веб-обои → Мышь доходит до страницы | интерактив, по умолчанию выкл. |
| Веб-обои → 30 / 60 кадров/с | ограничение частоты кадров страницы, по умолчанию 30 |
| Кадр из видео — обои системы | первый кадр видео ставится картинкой рабочего стола (по умолчанию вкл.) |
| Вернуть прежние обои | ставит картинку, что была до первого кадра, и выключает синхронизацию |
| Запускать при входе | SMAppService, по умолчанию выкл. |

Выбор запоминается (UserDefaults `io.github.qokori.LiveWallpaper`): путь плюс закладка (bookmark), поэтому
переименованный или перенесённый файл или папка находятся. Экраны различаются по UUID дисплея — он не меняется
при переподключении монитора и перезагрузке.

Командная строка (для скриптов):

```sh
APP=~/Applications/LiveWallpaper.app/Contents/MacOS/LiveWallpaper
$APP --video ~/Movies/clip.mov                      # видео на все экраны
$APP --web ~/Sites/my-wallpaper                     # папка с index.html, файл .html или https://…
$APP --video-for <UUID дисплея> ~/Movies/other.mp4  # один экран (включает режим «своё на каждый экран»)
$APP --web-for <UUID дисплея> https://example.com/
$APP --fps 60                                       # частота кадров веб-обоев
$APP --restore-wallpaper                            # вернуть прежнюю картинку рабочего стола и выйти
LW_DIAG=1 $APP                                      # журнал событий в stderr, замер шва петли, Web Inspector
```

`LW_IGNORE_OCCLUSION=1` — играть даже под окнами (только для замеров).

## Веб-обои

- **Источник.** Адрес `http(s)` или локальная папка / `.html`. Локальная страница грузится через
  `loadFileURL(_:allowingReadAccessTo:)` с доступом ко всей своей папке: скрипты, шейдеры, картинки рядом с
  `index.html` подхватываются. Переходы за пределы папки (или на другой сайт для адреса) блокируются, чтобы клик
  по ссылке не увёл обои со страницы.
- **Звук.** Медиа со звуком не запускается само (нет жеста пользователя), видео без звука играет.
- **Пауза.** Те же причины, что у видео (окно перекрыто, блокировка, сон, Low Power Mode, батарея). Пауза в два
  слоя: внедрённый скрипт сразу перестаёт вызывать колбэки `requestAnimationFrame` и замораживает CSS-анимации и
  медиа, затем веб-вью скрывается, и WebKit считает страницу невидимой (кадров нет, таймеры притормаживаются).
  Снимок, сделанный перед скрытием, остаётся на экране — на паузе виден последний кадр, а не чёрный экран.
- **Ограничение FPS.** Тот же скрипт пропускает кадры: колбэки `requestAnimationFrame` идут не чаще 30 или 60 раз
  в секунду. Действует на WebGL/canvas-анимации; CSS-анимации и `setInterval` идут своим ходом.
- **Интерактив.** Иконки Finder лежат в окне *над* обоями, поэтому окно обоев всегда пропускает мышь насквозь —
  иначе иконки перестали бы работать. Когда включено «Мышь доходит до страницы», приложение следит за мышью
  глобально (`NSEvent.addGlobalMonitorForEvents`, разрешение «Универсальный доступ» для мыши не нужно) и, если
  курсор над пустым рабочим столом (нет окон, Dock и строки меню над точкой), передаёт странице `pointermove` /
  `mousemove`, `pointerdown` / `mousedown`, `pointerup` / `mouseup` / `click` в координатах страницы.
  Ограничения: события синтетические (`isTrusted == false`), клик по рабочему столу получают и Finder, и страница
  (Finder снимает выделение иконок; если в macOS включено «Нажатие на обои — показать рабочий стол», окна
  разъедутся), колесо прокрутки и клавиатура не передаются.
- **Картинка рабочего стола** для веб-обоев не меняется (кадр ставится только из видео).
- **Отладка страницы.** С `LW_DIAG=1` страницу можно открыть в Safari → Разработка → Web Inspector.

Примеры (свой код, без чужих ассетов):

- `examples/aurora-shader/` — WebGL-шейдер «северное сияние», свечение следует за мышью. Рисует один пиксель
  шейдера на CSS-пиксель (на Retina это четверть пикселей экрана; `?scale=2` — полное разрешение).
- `examples/soft-lights/` — только CSS: три мягких пятна света медленно плывут, четвёртое следует за мышью.

## Как устроено

- **Окно** (`WallpaperWindow`): без рамки, всегда `ignoresMouseEvents`, `canJoinAllSpaces + stationary +
  ignoresCycle`, уровень `kCGDesktopWindowLevel + 1`. Картинка рабочего стола системы лежит ниже (desktop − 2 на
  проверенном Маке), иконки Finder — выше (desktop + 20). На одном уровне с картинкой не ставим: системное окно
  может перекрыть нас после смены Space.
- **Экраны** (`ScreenReconciler` в `WallpaperCore` решает, `WallpaperController` выполняет): одно окно на дисплей.
  На `didChangeScreenParameters` и после пробуждения окна создаются, подгоняются под новый размер или закрываются.
  Новый источник готовится в скрытом окне и показывается на первом кадре, старое окно закрывается после — рабочий
  стол не мигает чёрным.
- **Видео** (`LoopingPlayer`, `VideoContent`): `AVQueuePlayer` + `AVPlayerLooper`, без звука, `resizeAspectFill`,
  `preventsDisplaySleepDuringVideoPlayback = false` (обои не держат экран включённым). Петля строится из
  композиции, где есть **только видеодорожка**: если звуковая дорожка длиннее картинки (частый случай — AAC
  padding), плеер держал бы последний кадр на каждом круге.
- **Веб** (`WebContent`, `WebPageScript`, `PointerForwarder`): см. выше.
- **Паузы** (`PausePolicy` в `WallpaperCore`, `SystemMonitor`): окно перекрыто (`occlusionState`: fullscreen-
  приложение, другой Space, Mission Control, экран блокировки), экран заблокирован (`com.apple.screenIsLocked` и
  `CGSessionCopyCurrentDictionary` при старте), экраны спят, система спит, сеанс неактивен (быстрая смена
  пользователя), Low Power Mode (`isLowPowerModeEnabled`), по желанию — питание от батареи (IOKit).
- **Картинка рабочего стола** (`DesktopPictureMemory` в `WallpaperCore` решает, `SystemWallpaper` выполняет):
  первый кадр (`AVAssetImageGenerator`, точный кадр) пишется JPEG в
  `~/Library/Application Support/LiveWallpaper/Frames/` и ставится через `NSWorkspace.setDesktopImageURL` с
  заливкой как у видео. Видео стартует с того же кадра, поэтому вход в систему → запуск приложения проходит без
  скачка. Прежняя картинка запоминается по дисплею один раз; собственные кадры не запоминаются.

## Тесты

`swift test` — 40 тестов логики, без экрана и без изменения системы:

- пауза: каждая причина, приоритет, fullscreen на одном экране ставит на паузу только его, блокировка — все;
- экраны: подключение и отключение монитора, смена разрешения, новый выбор при загрузке старого, отказ без
  бесконечных повторов;
- картинка рабочего стола: имя файла кадра, «запомнить прежнюю только раз и не свою», возврат только на
  подключённых экранах;
- веб: разбор адреса, папка → `index.html`, переходы только внутри папки, попадание курсора на пустой стол,
  перевод координат;
- внедрённый скрипт в JavaScriptCore с поддельным дисплеем 60 Гц: 30 и 60 кадров/с, пауза останавливает кадры,
  продолжение их возвращает, смена FPS на лету, события мыши доходят до страницы;
- шов петли: измеритель стыка.

## Ручная проверка

Скрипты в `scripts/dev/` меняют состояние Мака (fullscreen-окно, виртуальный дисплей, картинка рабочего стола).
Запускайте их на тестовом Маке или когда за ним никто не работает.

1. **Петля видео.** `LW_DIAG=1 build/LiveWallpaper.app/Contents/MacOS/LiveWallpaper --video clip.mov` — в журнале
   строки `seam error` должны быть по модулю меньше длительности кадра.
2. **Fullscreen.** Развернуть любое приложение на весь экран (зелёная кнопка) → в журнале `pause [occluded]` для
   этого экрана, другие экраны играют; выйти из fullscreen → `play`. Без журнала: в Мониторе активности CPU
   процесса LiveWallpaper падает до 0.
3. **Второй монитор.** Подключить монитор → на нём через долю секунды те же обои (или общие в режиме «своё на
   каждый экран»); сменить разрешение в Настройках → Мониторы → обои заполняют экран; отключить → окно исчезает,
   на встроенном экране всё играет.
4. **Картинка рабочего стола.** С включённым «Кадр из видео» выбрать видео → в Настройках → Обои стоит кадр;
   открыть Mission Control → на текущем Space тот же кадр; «Вернуть прежние обои» → прежняя картинка. Если на
   разных Space разные картинки — заранее записать их: вернётся только текущая.
5. **Веб-обои.** Выбрать `examples/aurora-shader` → сияние плывёт. Пауза из меню → картинка замирает, CPU
   процессов `com.apple.WebKit.WebContent` и `com.apple.WebKit.GPU` падает почти до 0. 60 кадров/с → движение
   плавнее, нагрузка выше. «Мышь доходит до страницы» → свечение идёт за курсором над пустым столом и не реагирует
   над окнами; иконки выделяются и открываются как обычно.
6. **Замер.** Закрыть окна, отключить зарядку, затем
   `scripts/dev/measure.sh clip.mov 120` и `LW_FPS=30 scripts/dev/measure.sh examples/aurora-shader 120`
   (и то же с `LW_FPS=60`). Скрипт сам запускает и закрывает приложение.

## Замеры

`scripts/dev/measure.sh`: 60 с без приложения, затем 60 с с приложением. Считает CPU% и «энергетическое
воздействие» (`top`) приложения и запущенных им служб (`VTDecoderXPCService` — аппаратное декодирование видео,
`com.apple.WebKit.*` — веб-страница), CPU WindowServer, загрузку GPU и среднюю мощность системы по датчику батареи.
`powermetrics` не используется (нужен sudo).

| Источник, экран 2940×1912 | CPU приложения | CPU служб | Энерговоздействие (прил. + службы) |
| --- | --- | --- | --- |
| 4K HEVC 60 к/с, 30 Мбит/с, играет | 1,0 % | 1,3 % (декодер) | 1,1 + 1,3 |
| то же на паузе (экран заблокирован) | 0,0 % | 0,0 % | 0,0 |
| веб, `aurora-shader`, 30 и 60 к/с | не замерено | не замерено | — |

Оговорки к замеру видео: стол не был пустым (окна были открыты), а на Маке параллельно шла другая работа —
WindowServer до запуска показывал 41 % CPU, GPU 34 %, и эти числа скакали сильнее вклада обоев. Поэтому разница
WindowServer / GPU / мощности системы «до и после» не говорит о цене обоев и не приводится.

## Ограничения

- Картинка рабочего стола ставится только **на текущем Space** каждого экрана (так работает
  `setDesktopImageURL`). Приложение помнит одну прежнюю картинку на экран и возвращает её на текущий Space: если
  на разных Space были разные картинки, на остальных их придётся выбрать заново. Публичного API, чтобы различать
  Space, нет.
- «Вернуть прежние обои» возвращает файл-картинку. Динамические обои и заставки Apple (Aerial) так не вернуть —
  их выбирают заново в Настройках.
- Одно и то же видео на N экранах = N декодеров; одна и та же страница = N веб-вью.
- На экране блокировки и в Mission Control — статичная картинка, не видео.
- Шов петли убирает плеер, но не сам ролик: последний кадр должен переходить в первый.
- При выходе из приложения картинкой рабочего стола остаётся первый кадр (так вход в систему совпадает с началом
  видео). Убрать — «Убрать обои» или «Вернуть прежние обои».
- «Запускать при входе» требует, чтобы приложение лежало в постоянном месте (`~/Applications`); macOS может
  попросить разрешение в Настройках → Основные → Объекты входа.
- Ограничение FPS и мгновенная пауза через скрипт действуют на главный фрейм; вложенные фреймы (iframe) идут без
  ограничения FPS и останавливаются скрытием веб-вью.
- Не в песочнице, подпись ad-hoc, без нотаризации.

## Файлы

- `Sources/WallpaperCore/` — логика без AppKit: `PausePolicy`, `ScreenReconciler`, `DesktopPictureMemory`,
  `WallpaperAssignments`, `WebAddress` / `LocalPage` / `DesktopPointer`, `WebPageScript`, `LoopSeamMeter`.
- `Sources/LiveWallpaper/` — приложение: окно, видео, веб, контроллер экранов, системные события, картинка
  рабочего стола, меню.
- `examples/` — примеры веб-обоев.
- `scripts/build-app.sh` — сборка .app.
- `scripts/dev/` — ручные проверки: `windows.swift` (слои окон, только чтение), `fullscreen-probe.swift`,
  `virtual-display.m` (приватный `CGVirtualDisplay`, только для проверки, в приложение не входит), `measure.sh`.
