# Live Wallpaper для macOS

Живые обои для Mac: видео, анимированная GIF или веб-страница (HTML/CSS/JS, WebGL-шейдеры) на рабочем столе под иконками.
Приложение живёт в строке меню; главное окно (библиотека, экраны, настройки) открывается из меню или при запуске
из «Программ», и пока оно открыто, в Dock есть иконка. AppKit + AVFoundation + WebKit, SwiftUI для окна и меню,
без сторонних зависимостей. Лицензия MIT.

**Статус:** видео-обои проверены вживую на MacBook (Apple M5, macOS 27.0.1); веб-обои собраны и покрыты тестами,
но вживую ещё не запускались — см. «Ручная проверка». Главное окно (0.2) проверено юнит-тестами и рендером
в offscreen-битмап; живой прогон — выбор файла листом, иконка в Dock при открытии и закрытии окна — ещё впереди. GIF (0.3) проверена юнит-тестами и замером без окна; на живом экране не запускалась. Проекты Wallpaper Engine (0.4, 0.5): видео, веб и сцены проверены юнит-тестами (сцены — ещё и в веб-окне вне экрана по пикселям); на живом экране не запускались.

## Сборка и запуск

Нужен Xcode с Swift 6 (проверено на Xcode 27.1, Swift 6.4), macOS 14 или новее.

```sh
git clone https://github.com/qokori/live-wallpaper-mac.git
cd live-wallpaper-mac
swift test                               # тесты логики, модели приложения, окна и слоя GIF
./scripts/build-app.sh                   # build/LiveWallpaper.app + копия в ~/Applications
SKIP_INSTALL=1 ./scripts/build-app.sh    # только build/, ничего не устанавливает
open ~/Applications/LiveWallpaper.app
```

Сборка universal (arm64 + x86_64), подпись ad-hoc, без нотаризации. Логотип (чёрные волнистые полосы) рисуется кодом (`Sources/LiveWallpaper/Logo.swift`; `scripts/make-icon.swift` берёт его для иконки приложения, строка меню и окно — тот же рисунок как template-картинка), иконка пересобирается при каждом `build-app.sh`.

### Установочный образ

```sh
SKIP_INSTALL=1 ./scripts/build-app.sh
./scripts/make-dmg.sh build/LiveWallpaper.app build/LiveWallpaper.dmg
```

Образ открывается окном со своим фоном (`scripts/dmg-background.swift`: белая страница, чёрные волнистые полосы логотипа, стрелка от приложения к Applications,
строка про первый запуск), заданным размером и крупными иконками на своих местах; у тома иконка приложения. Расположение
окна записывает [dmgbuild](https://github.com/dmgbuild/dmgbuild) (`scripts/dmg-settings.py`): Finder не открывается,
AppleScript не запускается. При первом запуске dmgbuild (закреплённая версия) ставится в `build/dmg-venv`, для этого один раз
нужна сеть; в систему ничего не ставится. Как будет выглядеть окно, можно посмотреть, ничего не монтируя:
(`dmg-background.swift` вместе с `Sources/LiveWallpaper/Logo.swift` собирается `swiftc`, как в `scripts/make-dmg.sh`; команда `preview <AppIcon.icns> preview.png`).

### Первый запуск

Gatekeeper при первом запуске покажет «Apple не удалось подтвердить…». Сначала перенесите приложение в «Программы»
(из образа не запускайте), затем один раз:

1. В окне предупреждения нажмите **Готово** (не «Переместить в Корзину»).
2. «Системные настройки» → «Конфиденциальность и безопасность» → внизу «LiveWallpaper заблокирован» →
   **Всё равно открыть** → пароль или Touch ID.

Либо в Терминале: `xattr -dr com.apple.quarantine /Applications/LiveWallpaper.app`, затем запуск как обычно.

На macOS 14 также работает правый клик → **Открыть** → **Открыть**; на macOS 15 и новее этот способ больше не
обходит проверку.

## Установка одной командой

```sh
curl -fsSL https://raw.githubusercontent.com/qokori/live-wallpaper-mac/main/scripts/install.sh | bash
```

Скачивает последний релиз (`bash -s -- --version 0.4.0` — указанный), сверяет SHA-256 с `.sha256` из релиза, распаковывает через
`ditto` и ставит `LiveWallpaper.app` в `/Applications` (если нет прав — в `~/Applications`). Без sudo. Файл, скачанный `curl`, не
получает карантин, поэтому предупреждения Gatekeeper «Apple не удалось подтвердить…» нет; скрипт карантин не трогает. Если приложение
запущено, скрипт просит его закрыть и ничего не меняет. Приложение по-прежнему подписано ad-hoc и не нотаризовано. Скрипт:
[scripts/install.sh](scripts/install.sh).

## Главное окно

Открывается пунктом меню «Открыть Live Wallpaper…», при запуске из «Программ» и по клику на иконку в Dock.
Пока окно открыто, у приложения есть иконка в Dock; закрыли окно — снова только строка меню, обои играют дальше.
При запуске при входе и из командной строки окно не открывается.

| Вкладка | Что есть |
| --- | --- |
| Библиотека | сетка карточек: превью (первый кадр видео; у веб-обоев — `preview.png` / `thumbnail.jpg` из папки, если есть), название, тип, «На экране: …». «Добавить»: видео (можно несколько), GIF или APNG, папка или `.html`, адрес `https://…`; файлы можно перетащить в окно. Двойной клик — на все экраны; кнопки внизу и контекстное меню — «На все экраны», «На экран…», «Убрать из библиотеки» (файл остаётся на диске, играющие обои не прерываются) |
| Экраны | список мониторов: что стоит, «Играет» или причина паузы; «Своё на каждый экран»; «Поставить из библиотеки», «Масштаб» и «Как общие» для экрана |
| Настройки | масштаб видео, частота кадров сцен и веб-обоев (15 / 30 / 60), качество сцен (экономное / по экрану / максимальное) и мышь на странице, пауза вручную и от батареи, «Кадр из видео — обои системы», «Вернуть прежние обои», «Запускать при входе» |

Выбор файлов — лист (sheet) на окне, не модальный цикл. Звука нет: обои играют без звуковой дорожки.
Библиотека хранится в `~/Library/Application Support/LiveWallpaper/library.json`; при первом запуске версии 0.2
в неё попадают обои, выбранные раньше.

## Меню

Быстрые действия; выбор файлов и экранов — в окне.

| Пункт | Что делает |
| --- | --- |
| строка статуса | «Играет», «Пауза: обои закрыты окнами», «Играет на 1 из 2 экранов»… |
| Открыть Live Wallpaper… | главное окно |
| Поставить на все экраны | подменю: обои из библиотеки |
| Убрать обои | убирает обои и возвращает прежнюю картинку рабочего стола |
| Пауза | вручную (не запоминается между запусками) |
| Пауза от батареи | пауза, пока Мак работает от батареи (по умолчанию выкл.) |
| Вернуть прежние обои | ставит картинку, что была до первого кадра, и выключает синхронизацию |
| Запускать при входе | SMAppService, по умолчанию выкл. |

Выбор запоминается (UserDefaults `io.github.qokori.LiveWallpaper`): путь плюс закладка (bookmark), поэтому
переименованный или перенесённый файл или папка находятся. Экраны различаются по UUID дисплея — он не меняется
при переподключении монитора и перезагрузке.

Командная строка (для скриптов):

```sh
APP=~/Applications/LiveWallpaper.app/Contents/MacOS/LiveWallpaper
$APP --video ~/Movies/clip.mov                      # видео на все экраны
$APP --video ~/Pictures/cat.gif                    # GIF (или .apng) на все экраны — тот же флаг, что у видео
$APP --web ~/Sites/my-wallpaper                     # папка с index.html, файл .html или https://…
$APP --video-for <UUID дисплея> ~/Movies/other.mp4  # один экран (включает режим «своё на каждый экран»)
$APP --web-for <UUID дисплея> https://example.com/
$APP --we ~/Workshop/1234567890                     # проект Wallpaper Engine: папка, project.json или .pkg
$APP --we-for <UUID дисплея> ~/Workshop/1234567890/project.json
$APP --we-inspect ~/Workshop/1234567890            # состав проекта в stdout, без обоев
$APP --fps 60                                       # частота кадров сцен и веб-обоев: 15, 30 или 60
$APP --quality economy                              # качество сцен: economy, screen или maximum
$APP --restore-wallpaper                            # вернуть прежнюю картинку рабочего стола и выйти
LW_DIAG=1 $APP                                      # журнал событий в stderr, замер шва петли, Web Inspector
```

`LW_IGNORE_OCCLUSION=1` — играть даже под окнами (только для замеров).

## GIF

GIF и APNG — отдельный вид обоев наравне с видео и веб-страницей (`GifContent`, `FrameTimeline`).

- **Добавить:** «Библиотека → Добавить → GIF…», перетащить файл в окно или `--video файл.gif` / `--video-for <UUID> файл.gif`
  (`--video` понимает по расширению `.gif`, `.apng` и `.png` (APNG обычно сохраняют как .png; статичный .png отклоняется)). В файле должно быть больше одного кадра, иначе — понятная ошибка.
- **Анимация:** у каждого кадра своя задержка; задержка 0,01 с и меньше читается как 0,1 с, как в браузерах (так делают
  кодировщики, которые пишут 0 вместо «как можно быстрее»). Повтор бесконечный, счёт идёт по часам, поэтому пауза и
  запоздавший кадр не сдвигают ритм.
- **Масштаб:** «Заполнить / По размеру / Растянуть» работает как у видео (`contentsGravity` слоя); первый кадр можно ставить
  картинкой рабочего стола («Кадр из видео или GIF — обои системы»).
- **Пауза:** те же причины, что у видео; на паузе таймер остановлен, кадры не декодируются.
- **Память:** кадры декодируются по одному в фоновой очереди. Если все кадры в раскодированном виде укладываются в 64 МБ,
  они остаются в памяти (при проигрывании ничего не декодируется); иначе хранятся только текущий кадр и следующий.
  Картинка больше экрана раскодируется в размер экрана. Карточка в библиотеке берёт превью первого кадра
  в размере карточки (640 px), а не весь GIF.
- **Звука нет.**

Замер (Apple M5, без окна — работа оконного сервера не входит; `LW_MEASURE`, `Tests/LiveWallpaperTests/GifMeasureTests.swift`):

| GIF | файл | в раскодированном виде | режим | память процесса | ЦП, ядро |
| --- | --- | --- | --- | --- | --- |
| 480×270, 60 кадров, 20 к/с | 1,0 МБ | 30 МБ | все кадры в памяти | +8 МБ | 2,7 % |
| 1280×720, 60 кадров, 25 к/с | 5,0 МБ | 211 МБ | по одному | +17 МБ | 23,7 % |
| 1920×1080, 120 кадров, 25 к/с | 18,1 МБ | 949 МБ | по одному | +35 МБ | 38,8 % |

Большой GIF экономит память ценой процессора (декодирование кадра 1080p — около 12 мс); маленький почти ничего не стоит.
Порог — `FrameCachePolicy.budget`.

## Масштаб

Как видео ложится на экран, когда пропорции ролика и экрана не совпадают.

| Режим | Видео (`AVPlayerLayer.videoGravity`) | Картинка рабочего стола (`setDesktopImageURL`) |
| --- | --- | --- |
| Заполнить (по умолчанию) | `resizeAspectFill`: экран закрыт целиком, края, что не влезли, обрезаются | `imageScaling` = `scaleProportionallyUpOrDown`, `allowClipping` = да |
| По размеру | `resizeAspect`: виден весь кадр, остаток экрана — чёрные поля | `scaleProportionallyUpOrDown`, `allowClipping` = нет |
| Растянуть | `resize`: кадр растянут на весь экран, пропорции не сохраняются | `scaleAxesIndependently`, `allowClipping` = нет |

- Выбор устроен как источник: в обычном режиме один на все экраны; в режиме «Своё на каждый экран» на вкладке «Экраны»
  у экрана есть свой «Масштаб» с пунктом «Как общий» — экран без своего выбора берёт общий.
- Масштаб хранится отдельно от источников (UserDefaults, ключ `scaling`): новый ролик и «Убрать обои» его не
  сбрасывают.
- Новый режим применяется сразу, видео не перезагружается. Если включено «Кадр из видео — обои системы», картинка
  рабочего стола ставится заново с тем же режимом (как и всякая установка картинки — на текущем Space).
- Для веб-обоев пункт неактивен: страница сама раскладывается по окну. Общий «Масштаб» неактивен, когда общие
  обои — веб-страница; «Масштаб» экрана — когда на этом экране веб-страница.
- Поля в режиме «По размеру» на картинке рабочего стола macOS заливает своим цветом: приложение передаёт только
  `imageScaling` и `allowClipping`.

## Веб-обои

- **Источник.** Адрес `http(s)` или локальная папка / `.html`. Локальная страница грузится через
  `loadFileURL(_:allowingReadAccessTo:)` с доступом ко всей своей папке: скрипты, шейдеры, картинки рядом с
  `index.html` подхватываются. Переходы за пределы папки (или на другой сайт для адреса) блокируются, чтобы клик
  по ссылке не увёл обои со страницы.
- **Звук.** Медиа со звуком не запускается само (нет жеста пользователя), видео без звука играет.
- **Пауза.** Те же причины, что у видео (окно перекрыто, блокировка, сон, Low Power Mode, батарея). Пауза в два
  слоя: внедрённый скрипт сразу перестаёт вызывать колбэки `requestAnimationFrame` и замораживает CSS-анимации и
  медиа, затем веб-вью скрывается, и WebKit считает страницу невидимой (кадров нет, таймеры притормаживаются).
  Снимок, сделанный перед скрытием, остаётся на экране — на паузе виден последний кадр, а не чёрный экран.
- **Ограничение FPS.** Тот же скрипт пропускает кадры: колбэки `requestAnimationFrame` идут не чаще 15, 30 или 60 раз
  в секунду. Действует на WebGL/canvas-анимации; CSS-анимации и `setInterval` идут своим ходом.
- **Интерактив.** Иконки Finder лежат в окне *над* обоями, поэтому окно обоев всегда пропускает мышь насквозь —
  иначе иконки перестали бы работать. Когда включено «Мышь доходит до страницы», приложение следит за мышью
  глобально (`NSEvent.addGlobalMonitorForEvents`, разрешение «Универсальный доступ» для мыши не нужно) и, если
  курсор над пустым рабочим столом (нет окон, Dock и строки меню над точкой), передаёт странице `pointermove` /
  `mousemove`, `pointerdown` / `mousedown`, `pointerup` / `mouseup` / `click` в координатах страницы.
  Ограничения: события синтетические (`isTrusted == false`), клик по рабочему столу получают и Finder, и страница
  (Finder снимает выделение иконок; если в macOS включено «Нажатие на обои — показать рабочий стол», окна
  разъедутся), колесо прокрутки и клавиатура не передаются.
- **Картинка рабочего стола** для веб-обоев не меняется (кадр ставится только из видео).
- **Отладка страницы.** С `LW_DIAG=1` страницу можно открыть в Safari → Разработка → Web Inspector.

Примеры (свой код, без чужих ассетов):

- `examples/aurora-shader/` — WebGL-шейдер «северное сияние», свечение следует за мышью. Рисует один пиксель
  шейдера на CSS-пиксель (на Retina это четверть пикселей экрана; `?scale=2` — полное разрешение).
- `examples/soft-lights/` — только CSS: три мягких пятна света медленно плывут, четвёртое следует за мышью.

## Wallpaper Engine

Проекты Wallpaper Engine (папки Workshop) — отдельный вид обоев (`WallpaperSource.Kind.wallpaperEngine`, модуль `WallpaperEngineKit`).
Wallpaper Engine существует только под Windows: папки проектов нужно скопировать на Mac целиком.

- **Добавить:** «Библиотека → Добавить → Wallpaper Engine…» (папка проекта, `scene.pkg` или `project.json`), перетащить папку, `.pkg` или
  `project.json` в окно, или `--we <путь>` / `--we-for <UUID дисплея> <путь>`. В любом случае в библиотеку попадает **папка проекта**
  (закладка на неё), название берётся из `title`. `.pkg` без `project.json` рядом отклоняется; установщик macOS с тем же расширением
  (сигнатура `xar!`) отклоняется с пояснением. Папки и пакеты не копируются и не распаковываются.
- **Что показывается** (по `type` в `project.json`):
  - `video` — файл из `file` через `VideoContent`; mp4, m4v, mov. webm, avi и wmv отклоняются с понятным текстом;
  - `web` — страница из `file` через `WebContent`; страница получает привычный ей `window.wallpaperPropertyListener`:
    `applyGeneralProperties({fps})`, `applyUserProperties` со значениями по умолчанию из `general.properties`
    (после загрузки страницы и при позднем назначении слушателя), `setPaused` в такт нашей паузе. Функции
    `wallpaperRegister…Listener` (звук, медиа) существуют, но не вызываются: звукового спектра нет;
  - `scene` — **рисуется** (с 0.5): `scene.pkg` читается из отображённого в память файла, страница на WebGL2 внутри `WebContent`
    берёт описание сцены и текстуры по схеме `lwscene://`. Рисуются слои-картинки (положение, поворот, масштаб, родители,
    цвет, яркость, прозрачность, обычное, полупрозрачное и аддитивное смешивание), видеослои из `.tex` (MP4 играет в `<video>`,
    без звука, по кругу), режимы `colorBlendMode` 1 («умножение») и 31 («экран»), `clearcolor`, вписывание и заполнение, параллакс
    за мышью (`cameraparallax*`, `parallaxDepth`; на всех экранах со сценой, не чаще 60 раз в секунду). Не рисуются: эффекты,
    частицы, анимация слоёв, текст, звук, SceneScript, 3D; они перечислены в журнале и в `--we-inspect`. Номера 1 и 31 выведены
    сверкой кадра с превью образца; другие номера рисуются как обычное смешивание, их список виден в журнале. Если сцену нарисовать
    нельзя (нет картинок, повреждён пакет), показывается `preview` (`preview.gif` играет как GIF) с пометкой «сцена: пока превью»;
  - `application` — программа для Windows, отклоняется.
- **Масштаб** «Заполнить / По размеру / Растянуть» действует на `video` и `scene`, не на `web`. Картинка рабочего стола: первый кадр
  видео; у сцены — снимок нарисованного кадра (после первого показа лежит в `~/Library/Caches/LiveWallpaper/WallpaperEngine/<ключ>/snapshot.png`,
  кеш чистится при удалении из библиотеки и при превышении 1 ГБ), пока снимка нет — предпросмотр; для веб-проектов не ставится.
- **Параллакс:** камера идёт за мышью, слои смещаются в обратную сторону, глубже (`parallaxDepth`) — сильнее; сдвиг в долях сцены
  `2 · amount · mouseinfluence · (положение − ½)`, сглаживание по `delay`. Формулы WE нет в открытом виде: константы подобраны по описанию, не сверены с Wallpaper Engine.
- **Библиотека и откат:** с 0.4.0 `library.json` читается по элементам: запись с незнакомым видом источника или повреждённая не
  показывается и **записывается обратно как есть**, библиотека не обнуляется. Версии 0.3.1 и старше не знают вида
  `wallpaperEngine`, при откате на них библиотека с такими записями будет прочитана как пустая и перезаписана. Файл, который не
  разбирается целиком, откладывается как `library.unreadable.json`.
- **`--we-inspect <путь>`** печатает тип, поля `project.json`, настройки с их значениями, версию пакета, список файлов и состав
  `scene.json` (объекты по видам, число эффектов) и завершается; ничего не распаковывается.
- **Тесты:** синтетика собирается кодом (`EngineFixtures`: `.pkg`, битые пакеты, варианты `project.json`); настоящие проекты
  Workshop в репозиторий не входят. `LW_WE_SAMPLES=<папка с папками проектов> swift test` дополнительно прогоняет локальные образцы,
  без переменной эти тесты ничего не делают.
- **Формат** `.pkg` (строка версии `PKGVxxxx`, число файлов, пути со смещениями и длинами, данные) описан по RePKG (MIT, notscuffed),
  код оттуда не переносился; см. `THIRD-PARTY-NOTICES.md`.

## Как устроено

- **Окно** (`WallpaperWindow`): без рамки, всегда `ignoresMouseEvents`, `canJoinAllSpaces + stationary +
  ignoresCycle`, уровень `kCGDesktopWindowLevel + 1`. Картинка рабочего стола системы лежит ниже (desktop − 2 на
  проверенном Маке), иконки Finder — выше (desktop + 20). На одном уровне с картинкой не ставим: системное окно
  может перекрыть нас после смены Space.
- **Экраны** (`ScreenReconciler` в `WallpaperCore` решает, `WallpaperController` выполняет): одно окно на дисплей.
  На `didChangeScreenParameters` и после пробуждения окна создаются, подгоняются под новый размер или закрываются.
  Новый источник готовится в скрытом окне и показывается на первом кадре, старое окно закрывается после — рабочий
  стол не мигает чёрным.
- **Видео** (`LoopingPlayer`, `VideoContent`): `AVQueuePlayer` + `AVPlayerLooper`, без звука, `videoGravity` по масштабу,
  `preventsDisplaySleepDuringVideoPlayback = false` (обои не держат экран включённым). Петля строится из
  композиции, где есть **только видеодорожка**: если звуковая дорожка длиннее картинки (частый случай — AAC
  padding), плеер держал бы последний кадр на каждом круге.
- **Веб** (`WebContent`, `WebPageScript`, `PointerForwarder`): см. выше.
- **Паузы** (`PausePolicy` в `WallpaperCore`, `SystemMonitor`): окно перекрыто (`occlusionState`: fullscreen-
  приложение, другой Space, Mission Control, экран блокировки), экран заблокирован (`com.apple.screenIsLocked` и
  `CGSessionCopyCurrentDictionary` при старте), экраны спят, система спит, сеанс неактивен (быстрая смена
  пользователя), Low Power Mode (`isLowPowerModeEnabled`), по желанию — питание от батареи (IOKit).
- **Картинка рабочего стола** (`DesktopPictureMemory` в `WallpaperCore` решает, `SystemWallpaper` выполняет):
  первый кадр (`AVAssetImageGenerator`, точный кадр) пишется JPEG в
  `~/Library/Application Support/LiveWallpaper/Frames/` и ставится через `NSWorkspace.setDesktopImageURL` с
  тем же масштабом, что у видео. Видео стартует с того же кадра, поэтому вход в систему → запуск приложения проходит без
  скачка. Прежняя картинка запоминается по дисплею один раз; собственные кадры не запоминаются.

## Тесты

`swift test` — тесты логики, без экрана и без изменения системы:

- пауза: каждая причина, приоритет, fullscreen на одном экране ставит на паузу только его, блокировка — все;
- экраны: подключение и отключение монитора, смена разрешения, новый выбор при загрузке старого, отказ без
  бесконечных повторов;
- картинка рабочего стола: имя файла кадра, «запомнить прежнюю только раз и не свою», возврат только на
  подключённых экранах;
- веб: разбор адреса, папка → `index.html`, переходы только внутри папки, попадание курсора на пустой стол,
  перевод координат;
- внедрённый скрипт в JavaScriptCore с поддельным дисплеем 60 Гц: 30 и 60 кадров/с, пауза останавливает кадры,
  продолжение их возвращает, смена FPS на лету, события мыши доходят до страницы;
- масштаб: по умолчанию «Заполнить», выбор экрана с откатом на общий, режим → `videoGravity` и параметры картинки
  рабочего стола (сверка с константами AVFoundation и AppKit), пункт неактивен для веб-страниц;
- шов петли: измеритель стыка.

## Ручная проверка

Скрипты в `scripts/dev/` меняют состояние Мака (fullscreen-окно, виртуальный дисплей, картинка рабочего стола).
Запускайте их на тестовом Маке или когда за ним никто не работает.

1. **Петля видео.** `LW_DIAG=1 build/LiveWallpaper.app/Contents/MacOS/LiveWallpaper --video clip.mov` — в журнале
   строки `seam error` должны быть по модулю меньше длительности кадра.
2. **Fullscreen.** Развернуть любое приложение на весь экран (зелёная кнопка) → в журнале `pause [occluded]` для
   этого экрана, другие экраны играют; выйти из fullscreen → `play`. Без журнала: в Мониторе активности CPU
   процесса LiveWallpaper падает до 0.
3. **Второй монитор.** Подключить монитор → на нём через долю секунды те же обои (или общие в режиме «своё на
   каждый экран»); сменить разрешение в Настройках → Мониторы → обои заполняют экран; отключить → окно исчезает,
   на встроенном экране всё играет.
4. **Картинка рабочего стола.** С включённым «Кадр из видео» выбрать видео → в Настройках → Обои стоит кадр;
   открыть Mission Control → на текущем Space тот же кадр; «Вернуть прежние обои» → прежняя картинка. Если на
   разных Space разные картинки — заранее записать их: вернётся только текущая.
5. **Веб-обои.** Выбрать `examples/aurora-shader` → сияние плывёт. Пауза из меню → картинка замирает, CPU
   процессов `com.apple.WebKit.WebContent` и `com.apple.WebKit.GPU` падает почти до 0. 60 кадров/с → движение
   плавнее, нагрузка выше. «Мышь доходит до страницы» → свечение идёт за курсором над пустым столом и не реагирует
   над окнами; иконки выделяются и открываются как обычно.
6. **Масштаб.** Взять ролик с другими пропорциями, чем у экрана (4:3 или вертикальный). Масштаб → «По размеру»:
   виден весь кадр, по краям чёрные поля; «Растянуть»: кадр на весь экран, пропорции искажены; «Заполнить»: края
   обрезаны. С включённым «Кадр из видео» картинка рабочего стола (видна в Mission Control) ложится так же. В
   режиме «Своё на каждый экран» режим одного экрана не меняет другие. Для веб-страницы пункт серый.
7. **Замер.** Закрыть окна, отключить зарядку, затем
   `scripts/dev/measure.sh clip.mov 120` и `LW_FPS=30 scripts/dev/measure.sh examples/aurora-shader 120`
   (и то же с `LW_FPS=60`). Скрипт сам запускает и закрывает приложение.

## Замеры

`scripts/dev/measure.sh`: 60 с без приложения, затем 60 с с приложением. Считает CPU% и «энергетическое
воздействие» (`top`) приложения и запущенных им служб (`VTDecoderXPCService` — аппаратное декодирование видео,
`com.apple.WebKit.*` — веб-страница), CPU WindowServer, загрузку GPU и среднюю мощность системы по датчику батареи.
`powermetrics` не используется (нужен sudo).

| Источник, экран 2940×1912 | CPU приложения | CPU служб | Энерговоздействие (прил. + службы) |
| --- | --- | --- | --- |
| 4K HEVC 60 к/с, 30 Мбит/с, играет | 1,0 % | 1,3 % (декодер) | 1,1 + 1,3 |
| то же на паузе (экран заблокирован) | 0,0 % | 0,0 % | 0,0 |
| веб, `aurora-shader`, 30 и 60 к/с | не замерено | не замерено | — |

Оговорки к замеру видео: стол не был пустым (окна были открыты), а на Маке параллельно шла другая работа —
WindowServer до запуска показывал 41 % CPU, GPU 34 %, и эти числа скакали сильнее вклада обоев. Поэтому разница
WindowServer / GPU / мощности системы «до и после» не говорит о цене обоев и не приводится.

## Ограничения

- Картинка рабочего стола ставится только **на текущем Space** каждого экрана (так работает
  `setDesktopImageURL`). Приложение помнит одну прежнюю картинку на экран и возвращает её на текущий Space: если
  на разных Space были разные картинки, на остальных их придётся выбрать заново. Публичного API, чтобы различать
  Space, нет.
- «Вернуть прежние обои» возвращает файл-картинку. Динамические обои и заставки Apple (Aerial) так не вернуть —
  их выбирают заново в Настройках.
- Сцены Wallpaper Engine (0.5): без эффектов, частиц, анимации слоёв, текста, звука и SceneScript; сцена с эффектами выглядит проще, чем в
  Wallpaper Engine. Сцена с тремя видеослоями 4K тяжёлая: замер на образце (30 к/с, вне экрана, отладочная сборка) — около 2 ГБ памяти
  у веб-процессов и около 40 % ядра против 30 МБ и 3 % у одного видео 4K (декодер видео в систему не входит). Звуковой спектр
  и медиаинформация для веб-проектов Wallpaper Engine не передаются. Видео webm, avi и wmv macOS не воспроизводит.
- Одно и то же видео на N экранах = N декодеров; одна и та же страница = N веб-вью.
- Качество сцен: картинки ограничиваются один раз, по размеру холста при загрузке страницы (позднее изменение
  разрешения или более крупный экран оставляют их мелкими); приложение держит картинки в полном размере, уменьшение
  делает страница, поэтому «экономное» экономит память страницы, но не приложения. Видео внутри сцен декодируется
  целиком и на уровень качества не реагирует; обычные видео и GIF настройки сцен не затрагивают.
- На экране блокировки и в Mission Control — статичная картинка, не видео.
- Шов петли убирает плеер, но не сам ролик: последний кадр должен переходить в первый.
- При выходе из приложения картинкой рабочего стола остаётся первый кадр (так вход в систему совпадает с началом
  видео). Убрать — «Убрать обои» или «Вернуть прежние обои».
- «Запускать при входе» требует, чтобы приложение лежало в постоянном месте (`~/Applications`); macOS может
  попросить разрешение в Настройках → Основные → Объекты входа.
- Ограничение FPS и мгновенная пауза через скрипт действуют на главный фрейм; вложенные фреймы (iframe) идут без
  ограничения FPS и останавливаются скрытием веб-вью.
- Не в песочнице, подпись ad-hoc, без нотаризации.

## Файлы

- `Sources/WallpaperCore/` — логика без AppKit: `PausePolicy`, `ScreenReconciler`, `DesktopPictureMemory`,
  `WallpaperAssignments`, `WallpaperScaling` / `ScalingChoices`, `WallpaperLibrary` / `LibraryStore` / `ApplyTarget`, `WebAddress` / `LocalPage` / `DesktopPointer`, `WebPageScript`, `LoopSeamMeter`, `JSONValue` (записи библиотеки, которые эта версия не читает).
- `Sources/WallpaperEngineKit/` — проекты Wallpaper Engine без AppKit: `EngineProject` (project.json), `PKGArchive`, `EngineLocation`, `EngineFileSystem`, `TexFile` / `DXTDecoder` (текстуры), `SceneDocument` / `SceneAssets` / `SceneRendererPage` (сцена и её страница), `EngineWebShim`, `EngineInspector`.
- `Sources/LiveWallpaper/` — приложение: обои на рабочем столе (видео, веб, контроллер экранов, системные
  события, картинка рабочего стола), меню; `Window/` — главное окно (библиотека, экраны, настройки).
- `examples/` — примеры веб-обоев.
- `scripts/build-app.sh` — сборка .app; `make-icon.sh` / `make-icon.swift` — иконка; `make-dmg.sh`, `dmg-background.swift`, `dmg-settings.py` — установочный образ.
- `scripts/dev/` — ручные проверки: `windows.swift` (слои окон, только чтение), `fullscreen-probe.swift`,
  `virtual-display.m` (приватный `CGVirtualDisplay`, только для проверки, в приложение не входит), `measure.sh`.
